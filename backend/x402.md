# Backend — x402 Payment Integration

> Every LLM call is paid with USDC via x402. **No OpenAI key.** Mode B (server payer wallet) is the MVP default; Mode A (user signs) is the V2 switch. Protocol concept: `../x402.md`.

---

## 1. The client flow (`lib/x402.ts`)

```
callLLM(prompt, tools)
   │
   ├─► POST gateway (no credentials)
   │
   ├─► 402 Payment Required
   │     { price_usd, network: solana-mainnet/devnet,
   │       recipient, facilitator_url }
   │
   ├─► guard: price > X402_MAX_COST_PER_TURN → ABORT (fail closed)
   │
   ├─► sign USDC-SPL transfer from payer wallet
   │
   ├─► retry request with payment proof header
   │
   └─► 200 → streamed LLM response
```

Key properties:
- **No standing credentials** — each call pays for itself
- **Cost cap before signing** — never pay more than configured per turn
- **Facilitator settles** — we don't run RPC-level payment logic; the gateway/facilitator does (Coinbase CDP free tier ~1k tx/mo)
- The payer wallet signs **only** x402 payment transfers — nothing else

---

## 2. Modes

| | A. User-pays (V2) | B. Prepaid agent wallet (V1 default) |
| --- | --- | --- |
| Who signs payment | User's Seed Vault via MWA (app-side) | Server payer wallet (this folder) |
| Backend holds key? | No | Yes — small balance, env-protected |
| UX | Tap per message | Seamless |
| Env | `X402_MODE=user` | `X402_MODE=prepaid` |

Mode B payer wallet policy:
- Funded with **test/devnet USDC** during development; small mainnet balance later
- **Separate wallet from everything else** — never shared with user funds
- Balance = maximum theoretical loss; keep it intentionally small

## 3. Gateway selection (to verify at integration time)

| Candidate | Notes | Verify |
| --- | --- | --- |
| Solvela (Solana-native) | USDC-SPL settlement on Solana — best stack fit | testnet E2E |
| BlockRun / xpaylabs (LLM gateways) | x402 LLM pay-per-call | availability |
| Generic gateway via `@x402/fetch` | works with any 402 endpoint | config |

**Decision gate:** gateway must (1) work on testnet, (2) support Solana USDC (preferred), (3) expose an OpenAI-compatible streaming endpoint we can pipe through Vercel AI SDK. If none qualify on day one, gate behind `X402_GATEWAY_URL` and keep a manual-payment stub for the demo — **never** introduce an OpenAI key as the default path.

## 4. Env & budgets

```env
X402_MODE=prepaid
X402_GATEWAY_URL=...              # chosen LLM gateway
X402_FACILITATOR_URL=https://api.cdp.coinbase.com/platform/v2/x402
X402_PAYER_PRIVATE_KEY=...        # server payer wallet (Mode B only)
X402_MAX_COST_PER_TURN=0.05       # USD — fail closed above this
X402_MAX_COST_PER_DAY=1.00        # USD — hard daily budget (both modes)
```

- Daily budget enforced server-side: once exceeded, chat replies "agent wallet needs top-up"
- Log every payment: `{turn, cost_usd, session_id, ts}` for the cost line in UI

---

## 5. Failure matrix

| Situation | Behavior |
| --- | --- |
| 402 price > cap | abort turn, "over budget" error bubble |
| Payer balance empty | `payment_required` error (mobile shows top-up card) |
| Gateway 5xx | retry once, then error bubble |
| Facilitator slow | timeout → retry with backoff |
| Mode A signature cancelled | continue turn with read-only answer (no paid call) |

---

## 6. Testing checklist

- [ ] Devnet: full chat turn pays via x402, cost line matches logged amount
- [ ] Payer wallet emptied → correct top-up prompt, no crash
- [ ] Cost cap hit → turn aborts before signing payment
- [ ] Gateway down → error bubble + retry path
- [ ] Daily budget rollover at midnight
- [ ] Mode A: user rejects signature → graceful fallback
